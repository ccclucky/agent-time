# 0001. Claude Code 耗时分析三态切分与多级下钻架构

## 状态 (Status)
accepted (2026-10-23)

## 决策背景 (Context)
原 `src/claude.ts` 时间分析缺乏一手实测依据，仅根据外部推测将用户输入到结束标记的粗跨度作为总耗时，且在遇到工具分支或子 Agent 记录时直接拦截报错；底层核心指标 `work_ms` 与 `human_ms` 均硬编码为 NULL，把等待人类审批和终端待命全部误计为 AI 工作耗时。同时，多会话与并发 Subagent 的多层级下钻（Drill-Down）能力缺失。

## 架构决策 (Decision)
1. **三态时间度量切分**：基于本地会话 JSONL 事件流（`tool_use` 与 `tool_result` 精准时间戳配对及原生 `turn_duration` 埋点），将时间严格切分为：
   - **纯工作耗时 (Active Work Duration)**：模型生成耗时 + 本地工具与脚本运行耗时；
   - **等待人审阅耗时 (Review Wait)**：Agent 触发权限确认或命令审批时的阻断挂起耗时；
   - **待命时长 (Standby Duration)**：轮次交割后终端静默等待下一次唤醒的空闲时长。
2. **多维聚合与六级穿透下钻体系**：统一构建「工具生态 ➔ 项目工程 ➔ 会话 ➔ 并发 Subagent ➔ 轮次 ➔ 原子事件」体系，支持在纯工作块中向下展开「模型生成总耗时、工具调用总耗时、网络与环境总耗时」及具体的执行脚本清单。
3. **解除子 Agent 一票否决拦截**：放开对 `agentId` 与 `isSidechain` 记录的硬拦截，将并发子 Agent 纳入多线程并发机时累加与物理跨度覆盖统计。

## 产生的影响与后果 (Consequences)
- 彻底消灭报表中一直为 NULL 的 `work_ms` 与 `human_ms`，提供真实可信的人机协同能效审计数据；
- 统计口径与本地日志解耦为两层：底层原子事件高保真解析 + 上层三态多维聚合展示；
- 需在下一步实现中改造 `src/claude.ts` 解析器与 `src/metrics.ts` 统计模型，并升级前端交互展示组件。
